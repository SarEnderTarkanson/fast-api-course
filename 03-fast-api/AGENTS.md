Routing and data patterns (concrete examples)
- Endpoints defined in `books.py`:
  - GET /books -> returns the whole BOOKS list
  - GET /books/{book_title} -> path param `book_title` (case-insensitive match using .casefold())
  - GET /books/?category=... -> query param `category` returns matching books
  - GET /books/{book_author}/?category=... -> path param `book_author` + query `category`
  - POST /books/create_book -> body (raw JSON) appended to BOOKS
  - PUT /books/update_book -> body (raw JSON) replaces matching title in BOOKS

Important implementation details agents must preserve
- Case-insensitive matching: code uses book.get('field').casefold() for comparisons — preserve this when adding or refactoring.
- Raw dicts: endpoints accept and append/replace plain dicts (Body()). There are no Pydantic schemas in this repo — keep request/response shapes compatible.
- Some endpoints do not return an explicit response after POST/PUT. If you change that behavior, update internal callers or tests accordingly.

Subtleties and potential conflicts to watch for
- Overlapping path patterns: `/books/{book_title}` and `/books/{book_author}/` both use a single path segment followed by optional trailing slash. Be careful when adding new path operations that could shadow existing ones.
- Trailing-slash differences matter here (`/books` vs `/books/`). Tests or clients that normalize trailing slashes may hit different handlers.

Testing & debugging notes
